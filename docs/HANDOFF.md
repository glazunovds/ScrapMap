# Состояние ScrapMap

Обновлено после сессии, в которой атлас тайлов перевели на процедурную
генерацию через игровой terrain API.

Репозиторий: https://github.com/glazunovds/ScrapMap
Игра: Scrap Mechanic 1.0.4.874, Windows x64

## Что изменилось в этой сессии

### Атлас тайлов генерируется из данных игры

Раньше карта рисовала ~43% тайлов из чужого скриншотного атласа
(`the1killer/sm_overview`, CC BY-NC-SA), остальное — схематично, а новые
start-area и quest-тайлы не имели top-down картинки вообще.

Теперь `Survival/Scripts/terrain/ScrapMapAtlasBake.lua` семплирует **каждый**
зарегистрированный тайл через `sm.terrainTile` и пишет по одному JSON на UUID в
`Survival/ScrapMapAtlas/`. `src-tauri/src/atlas_bake.rs` декодирует растры,
рисует PNG в `%LOCALAPPDATA%\ScrapMap\atlas\tiles\generated\` и проставляет
`topDownRelativePath` в манифесте — рендерер подхватывает их без изменений.

Результат: **493 из 493 тайлов**, 100% покрытие, ноль зависимости от
CC BY-NC-SA. Импорт `sm_overview` больше не используется
(`tools/tile-atlas/import-sm-overview.mjs` — мёртвый код).

Тайлы семплируются **без поворота** и без мировых эффектов, поэтому атлас
зависит только от сборки игры и одинаков для всех миров и обоих игроков.

### Что выяснилось по ходу (важное для будущих правок)

- **`getColorAt` возвращает не цвет, а тинт** поверх текстур материалов. Если
  брать только его, тайлы получаются почти белыми. Видимая поверхность — это
  `getMaterialAt`, свёрнутый в grass/sand/dirt/rock так же, как это делает сама
  игра в `GetEffectMaterialAt`.
- **`sm.json.fileExists` не видит файлы, записанные в этой же сессии.** Прогресс
  выпечки хранится в game storage. `Load()` вызывается несколько раз за загрузку
  мира, и проверка по каталогу перевыпекала одни и те же 40 тайлов бесконечно.
- **Lua пишет все числа в JSON как double** (`512.0`). Serde это не приводит к
  целым — нужен float-терпимый десериализатор.
- **Картинка тайла покрывает весь тайл**, а не клетку. Рендерер берёт срез по
  `xOffset`/`yOffset`; раньше тайл 4×4 рисовался целиком в каждой из 16 клеток.
- **Размеры тайлов идут до 16×16**, не до 4×4.
- **Вода**: только глубины мало — траншея от корабля уходит на несколько метров
  вниз и заливалась как река. Дно озёр семплируется как rock/sand и глубже трёх
  метров, траншея и просевшие дороги — dirt на глубине 1–3 м. Порог −2.5 м плюс
  требование «материал дна озера».

### Патч игры стал обратимым

`tools/game-patch.mjs` — `status` / `snapshot` / `apply` / `revert`.

Патч теперь чисто аддитивный: отдельные addon-файлы плюс один размеченный блок,
дописанный в конец штатного файла. `terrain_overworld.lua` только оборачивает
`Load()`; экспорт layout вынесен в `ScrapMapLayoutExport.lua`, а обращение к
`GetLegacyID` стало опциональным — правка `tile_database.lua` больше не нужна.

Причина: **игра сверяет контрольные суммы Lua-скриптов при подключении**
(`m_serverGameInfo.m_vecFileChecksums` в бинарнике). Модифицированные скрипты
не дают зайти на сервер с другими файлами. Оба игрока должны иметь
байт-идентичные файлы — см. `docs/MULTIPLAYER-TEST.md`.

`game-patch/vanilla/` (эталон для отката) намеренно **не в git**: это исходники
Axolot, их не следует распространять. Восстанавливается через проверку
целостности файлов Steam + `snapshot`.

### Прочее

- Туман войны снова можно выключить: `loadPoiFilters` сбрасывал настройку при
  каждой активации layout, хотя в приложении ею владеет профиль. По умолчанию
  по-прежнему включён.
- Устаревшие фотографии POI из `sm_overview` (в том числе `crashed_ship.jpg` со
  сдвигом −2/−2) снимаются с тайлов, для которых есть сгенерированная картинка.
- `tools/game-patch.mjs` ищет игру по стандартным папкам Steam, без зашитого
  локального пути.

## Как это запускать

```bash
node tools/game-patch.mjs apply     # поставить патч
pnpm tauri build --no-bundle        # собрать portable EXE
```

Дальше запустить игру через Steam с `-dev`, зайти в выживание — первая загрузка
мира печёт весь атлас (~20 секунд, один раз, прогресс в game storage). ScrapMap
конвертирует тайлы на старте и перепроверяет раз в 30 секунд.

Проверить выпечку:

```bash
SM="<путь к папке Scrap Mechanic>"
grep -E "SCRAPMAP_ATLAS_V1.(begin|done|fail)" "$(ls -t "$SM"/Logs/*.log | head -1)"
```

Ожидается `done|baked=493|failed=0|pending=0`.

Если менять палитру или рельеф — константы в начале `src-tauri/src/atlas_bake.rs`
(`SURFACE_PALETTE`, `HILLSHADE_STRENGTH`, `WATER_LEVEL`). Перегенерация не
требует игры: удалить PNG в `%LOCALAPPDATA%\ScrapMap\atlas\tiles\generated\` и
перезапустить ScrapMap.

## Что осталось

1. **Объекты не рисуются.** Корабль, склады, деревья и камни — это prefab/asset,
   а не рельеф. `getColorAt`/`getMaterialAt` описывают только землю. Чтобы их
   показать, нужно экспортировать `getAssetsForCell` / `getPrefabsForCell` /
   `getNodesForCell` / `getCreationsForCell` и рисовать иконками. Это же даст
   деревья и камни, из-за которых карта-образец выглядит живой.
2. **Мультиплеер не протестирован** с рабочим Lua-мостом. Инструкция для второго
   игрока — `docs/MULTIPLAYER-TEST.md`.
3. **Мёртвый код не вычищен**: `diagnostic_source.rs` (~1000 строк, JSON-канал
   без источника), `native_process.rs` (живой только `game_log_directory`),
   `game_build.rs` (не подключён, хеш устарел на версию), `rectifiedAtlasPreview`
   в `app.js` (недостижимая ветка), `src/sync/` и `src/data-sources/` (только
   интерфейсы), `tools/tile-atlas/import-sm-overview.mjs`,
   `src-tauri/examples/native_disasm.rs` (тянет `iced-x86`).
4. **Синхронизация фога и меток** между игроками (Cloudflare Worker) — не начата.
5. Порог воды −2.5 м подобран по данным текущей сборки; на других тайлах может
   потребоваться уточнение.

## Ограничения

- Никакого Cheat Engine, записи в память процесса и DirectX-хуков.
- Только portable EXE, без MSI/NSIS.
- Игровые PNG и чужие изображения не распространяются как свои ассеты.
- Любое изменение игры должно безопасно отключать несовместимый мост, а не падать.
